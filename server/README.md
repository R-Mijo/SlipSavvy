# Phone odds service — limited private beta

The backend has bounded authenticated `POST /api/game-reports`, offered alternate spread/total retrieval, and on-demand NFL player props. Individual alternate offers do not produce a supported win forecast or optimization. See [API contract](../docs/GAME_REPORT_API.md). Missing research/forecast sources stay explicit. The default free NWS weather mode applies only when event venue/roof evidence is established; `REPORT_WEATHER_MODE=disabled` prevents weather calls. The reviewed pilot covers Lumen Field weather, U.S. Bank Stadium's fixed indoor roof, and Lucas Oil Stadium's unresolved retractable state. Other venues remain unavailable. See [coverage, provenance and NWS contract](../docs/VENUE_WEATHER.md). No model or paid data subscription is installed.

The app browses active supported sports, upcoming games and pregame moneylines/spreads/totals from DraftKings and FanDuel via The Odds API. NFL adds on-demand passing/rushing main and alternate props through authenticated `GET /api/odds/props`, preserving provider player descriptions in mixed-market reports. Each one/two-market event request reserves one/two credits from the same ten-credit daily guard; cached subsets reuse the batch. Missing/stale/ambiguous offers remain unavailable. No forecast, wager placement or in-play selection. Provider titles are descriptive references, not sponsorship. Actual live prop coverage is not confirmed by synthetic tests.

Existing configured odds access is reused. Analyzed NFL games now also request free nflverse schedule/injury snapshots and, for props, exact roster/GSIS mapping. Missing/stale/ambiguous sources and unknown team/week coverage stay explicit; reported status is not confirmation that a player will play. No new key or subscription is required. The server requirements include free IANA timezone data; `NFL_RESEARCH_MODE=disabled` disables these source requests. See [source, identity and freshness limits](../docs/NFL_RESEARCH.md). Venue/roof/weather, usage and calibrated forecasts remain separate gaps.

For a new installation only, create a free odds-provider account and store `ODDS_API_KEY` in the hosting service's secret environment settings. Never put it in GitHub, Expo public variables, app.json or an APK. No key is committed here; completed user setup should be preserved.

For a Render test service: connect this repository's phone branch, choose Python and the Free instance, use build command `pip install -r server/requirements.txt` and start command `gunicorn server.odds:application --workers 1 --threads 4 --bind 0.0.0.0:$PORT`. Set secret variables `ODDS_API_KEY` and `ODDS_PREVIEW_TOKEN` (choose a random value for preview access). Use the resulting HTTPS URL as `EXPO_PUBLIC_ODDS_API_URL` for the mobile build, and the matching preview-access value as `EXPO_PUBLIC_ODDS_PREVIEW_TOKEN`. The latter is bundled with the test app and is only a casual-access gate, not production user authentication. The provider key remains server-only.

The service serializes requests, caches each sport/market and each requested event's alternate quotes for five minutes, and enforces a shared ten-credit/day paid-quota allowance per UTC day per process (`1` credit reserved before I/O for a one-market/one-region main lookup; `2` credits reserved before I/O for a two-market/one-region `alternate_spreads,alternate_totals` event lookup, including failed attempts; cache hits consume zero new credits). This is a testing guard only: counters/cache reset on restart. Free Render instances sleep and lose local state. Provider's free monthly quota remains the ultimate cap. Before production, add durable shared metering/cache, individual user authentication, per-user rate limits and monitoring. Do not expose this as a public standalone raw-data API or sell the feed itself. No cloud service, paid subscription or signing/build has been activated by adding these files.

Only the endpoint URL and private-beta access gate go in the EAS preview environment. On Windows PowerShell from `mobile/`, create the two public build variables (substitute the deployed URL and the same access value used by the server):

```powershell
npx.cmd eas-cli env:set --environment preview --name EXPO_PUBLIC_ODDS_API_URL --value https://YOUR-SERVICE.onrender.com --visibility plaintext
npx.cmd eas-cli env:set --environment preview --name EXPO_PUBLIC_ODDS_PREVIEW_TOKEN --value YOUR-PREVIEW-ACCESS-VALUE --visibility plaintext
npx.cmd eas-cli build --platform android --profile preview
```

Existing variables can also be managed in the EAS environment dashboard. The preview profile explicitly uses the `preview` environment. Local shell variables alone are not the remote build environment. Install the new APK; the previous installed build has no data browser. Record the tested commit/device and verify real quotes with their source before relying on them. Cold starts can take about a minute, so the phone allows a 90-second initial request timeout.

Refreshing one sport/market typically uses one credit and an event-specific two-market alternate lookup typically uses two credits; coverage, freshness and availability are provider dependent. This adapter does not establish commercial store eligibility.
